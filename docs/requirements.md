# 2027 诗词日历网页应用开发需求

## 一、项目介绍

开发一个具有东方美学、古典诗意、沉浸式视觉体验的 2027 年诗词日历网页应用。

用户每天打开网站时，自动展示当天的公历日期、农历日期、节气、传统节日，以及一首与当前日期、季节、节气、物候相匹配的中国古典诗词，并搭配一张具有艺术感的背景插画。

整个应用应当像一本精美的电子诗词画册，让用户在每天打开网站时，都能获得不同的视觉体验和诗意感受。

项目暂定名称：

- 中文名称：岁时有诗
- 英文名称：Poetic Days
- Slogan：一日一诗，四季皆景。

## 二、技术栈

严格使用以下技术栈：

- React
- TypeScript
- Vite
- Tailwind CSS
- pnpm
- ESLint
- Prettier
- GitHub Actions

其他辅助依赖可根据实际需求选择：

- lunar-typescript：农历、干支、节气计算及数据校验
- Motion（motion/react）：页面及交互动画
- Lucide React：图标
- dayjs：日期处理
- html-to-image：诗词卡片图片导出

优先采用 React Hooks 和函数式组件进行开发。

不需要后端服务，不需要数据库，不需要用户登录，不依赖付费 AI 接口。整个项目采用静态资源和本地 JSON 数据驱动，支持静态部署。

## 三、核心功能

### 3.1 每日一诗

用户进入网站时，默认展示北京时间对应的当天日期及诗词内容。

页面需要展示：

- 公历年份、月份、日期
- 星期
- 农历月份及日期
- 农历干支年份
- 生肖
- 当前季节
- 当天节气（如有）
- 当天传统节日（如有）
- 当日诗词名句
- 诗词完整原文
- 诗词名称
- 作者及朝代
- 白话译文
- 简短赏析
- 诗词主题标签
- 与诗词相匹配的背景插画

每天自动切换诗词，不需要用户手动刷新。

当页面跨越北京时间凌晨零点时，应自动更新当前日期和诗词内容。页面从后台恢复时，也需要重新检查日期。

同一天的诗词及背景图必须保持一致，不能每次刷新都随机变化。

### 3.2 诗词匹配规则

项目需要准备 2027 年全年共 365 天的诗词数据，每一天必须拥有独立的诗词记录。

诗词不能简单随机分配，应综合考虑以下因素：

1. 公历日期
2. 农历日期
3. 二十四节气
4. 中国传统节日
5. 当前季节
6. 季节性自然景观
7. 传统物候特征
8. 月相、团圆、思念等文化意象

匹配优先级：

传统节日 > 二十四节气 > 特殊农历日期 > 季节物候 > 普通生活意境。

例如：

- 元旦：海日生残夜，江春入旧年。
- 春节：爆竹声中一岁除，春风送暖入屠苏。
- 立春：律回岁晚冰霜少，春到人间草木知。
- 雨水：好雨知时节，当春乃发生。
- 清明：清明时节雨纷纷，路上行人欲断魂。
- 谷雨：谷雨如丝复似尘，煮瓶浮蜡正尝新。
- 夏至：昼晷已云极，宵漏自此长。
- 七夕：两情若是久长时，又岂在朝朝暮暮。
- 中秋：但愿人长久，千里共婵娟。
- 重阳：遥知兄弟登高处，遍插茱萸少一人。
- 霜降：停车坐爱枫林晚，霜叶红于二月花。
- 冬至：天时人事日相催，冬至阳生春又来。
- 大雪：忽如一夜春风来，千树万树梨花开。

以上为匹配示例，实际日期必须根据 2027 年中国农历及节气数据进行校验。

### 3.3 诗词选取风格

诗词整体偏向唯美、浪漫、治愈、清新、含蓄、空灵、具有画面感的风格。

优先选取以下主题：

- 春风
- 烟雨
- 山川
- 湖泊
- 明月
- 星河
- 花草
- 落日
- 云海
- 江南
- 四季
- 白雪
- 清风
- 田园
- 相思
- 团圆
- 时光
- 人间烟火

例如：

- 春水碧于天，画船听雨眠。
- 醉后不知天在水，满船清梦压星河。
- 疏影横斜水清浅，暗香浮动月黄昏。
- 落霞与孤鹜齐飞，秋水共长天一色。
- 掬水月在手，弄花香满衣。
- 行到水穷处，坐看云起时。
- 明月松间照，清泉石上流。
- 小楼一夜听春雨，深巷明朝卖杏花。
- 沾衣欲湿杏花雨，吹面不寒杨柳风。
- 水晶帘动微风起，满架蔷薇一院香。

优先使用唐诗、宋词、元曲、诗经以及其他具有古典文学价值的作品。

要求：

- 全年 365 天的核心诗句不能重复。
- 所有诗词必须真实存在。
- 作者、朝代、作品名称必须准确。
- 不允许使用 AI 编造的古诗词。
- 尽量避免过于悲观、压抑、战争、政治讽刺等主题。
- 特殊传统节日可根据其文化内涵适当调整。
- 完整原文与摘录名句必须来自同一作品。
- 优先选择已进入公有领域的古典作品。

### 3.4 四季主题

根据季节及节气自动调整页面的视觉氛围。

春季：

- 主色调：嫩绿、浅粉、米白
- 视觉元素：桃花、杏花、春雨、燕子、柳枝、江南水乡
- 整体氛围：清新、柔和、生机盎然

夏季：

- 主色调：青绿、湖蓝、浅青
- 视觉元素：荷花、竹林、湖泊、蝉鸣、晚霞、萤火虫
- 整体氛围：清凉、宁静、通透

秋季：

- 主色调：暖橙、金黄、枫红、棕色
- 视觉元素：桂花、枫叶、芦苇、明月、秋山
- 整体氛围：温暖、浪漫、悠远

冬季：

- 主色调：灰蓝、雪白、墨色、淡紫
- 视觉元素：雪山、寒梅、灯笼、松柏、雪夜
- 整体氛围：静谧、纯净、温馨

季节判断以中国传统节气为主要依据，即立春、立夏、立秋、立冬作为四季切换节点。

## 四、背景插画设计

每天的诗词必须搭配一张符合诗词意境的背景图片。

### 4.1 图片风格

优先采用以下艺术风格：

- 国风插画
- 中国传统水墨画
- 东方意境插画
- 手绘水彩
- 淡彩山水
- 工笔画
- 古典绘本
- 新中式插画
- 治愈系风景插画
- 极简留白插画

避免：

- 普通商业摄影
- 城市街拍
- 科技感背景
- 高饱和度卡通图片
- 与诗词无关的随机图片
- 带有明显水印的图片
- 画面中包含大量文字的图片

背景插画应具有足够的留白空间，方便诗词文字展示。

### 4.2 图片来源

可以从以下平台寻找适合的图片资源：

- Unsplash
- Pexels
- Pixabay
- Wikimedia Commons
- The Met Open Access
- Art Institute of Chicago Open Access
- Lorem Picsum
- 其他具有明确授权的免费图片平台

Lorem Picsum 主要用于开发阶段的占位图片，不应将随机摄影图片直接作为正式诗词插画。

正式背景图片应根据诗词意象进行人工或自动筛选，并将确定的图片 URL 写入对应的 JSON 数据。

不允许编造不存在的图片 URL。

优先使用允许网页展示及再分发的图片资源，并保留图片作者、来源、授权协议等信息。

对于允许下载并重新托管的图片，优先下载到项目本地，通过静态资源方式进行访问，避免第三方链接失效、防盗链和跨域问题。

### 4.3 图片匹配示例

诗词：春水碧于天，画船听雨眠。

背景：江南水乡、烟雨朦胧、乌篷船、水墨插画。

诗词：醉后不知天在水，满船清梦压星河。

背景：深蓝色星空、湖面倒影、孤舟、梦幻东方插画。

诗词：疏影横斜水清浅，暗香浮动月黄昏。

背景：月夜、梅花枝、静谧湖水、淡墨插画。

诗词：小荷才露尖尖角，早有蜻蜓立上头。

背景：夏日荷塘、嫩绿荷叶、蜻蜓、清新水彩插画。

诗词：忽如一夜春风来，千树万树梨花开。

背景：雪山、白雪覆盖的树林、冬日水墨插画。

### 4.4 图片加载优化

- 使用 WebP 或 AVIF 格式。
- PC 背景建议使用 1920×1080 或相近比例。
- 移动端优先使用适合竖屏裁切的图片。
- 预加载当天背景图。
- 在浏览器空闲时预加载前一天和后一天的背景图。
- 图片切换时使用淡入淡出动画。
- 加载期间使用与当前主题相匹配的渐变色占位。
- 图片加载失败时使用本地默认插画。
- 禁止一次性加载全年 365 张背景图片。
- 根据画面内容支持自定义 object-position。
- 保证诗词文字与背景之间具有足够的对比度。

## 五、UI 与视觉设计

### 5.1 整体设计理念

整体设计应具有高级感、文学感、艺术感和东方美学。

参考方向：

- 新中式美学
- 中国古典诗词画册
- 艺术杂志排版
- 东方水墨留白
- 博物馆数字展览
- 沉浸式动态壁纸

不要使用传统后台管理系统的设计风格。

不要堆砌大量卡片、按钮、边框和阴影。

避免过度使用玻璃拟态、渐变色及复杂装饰。

以背景插画和诗词排版作为整个页面的视觉核心。

### 5.2 首页布局

首页采用全屏沉浸式布局，至少占满一个可视区域。

顶部导航：

- 左侧展示项目 Logo 和名称“岁时有诗”。
- 右侧展示日历、收藏、设置、全屏等功能入口。
- 导航栏保持简洁，不遮挡背景插画。

主视觉区域：

- 使用当天的诗词插画作为全屏背景。
- 日期采用大字号、具有艺术感的排版。
- 农历、星期、节气作为辅助信息。
- 核心诗句采用大字号中文衬线字体。
- 作者、朝代、作品名称使用较小字号。
- 诗词区域可根据背景构图灵活调整位置。
- 支持横排和传统竖排诗词展示。

底部区域：

- 上一天
- 回到今天
- 下一天
- 查看完整诗词
- 收藏
- 分享
- 下载诗词卡片
- 年度进度

尽量采用轻量化图标按钮，不破坏整体画面的沉浸感。

### 5.3 字体设计

中文诗词优先使用：

- 思源宋体
- Noto Serif SC
- 其他具有明确开源授权的中文书法或衬线字体

普通功能文字使用：

- PingFang SC
- Noto Sans SC
- 系统默认无衬线字体

日期数字可以使用具有杂志排版感的英文衬线字体。

避免加载体积过大的完整中文字体文件，优先采用字体子集、按需加载或系统字体回退方案。

### 5.4 响应式适配

需要完整适配：

- PC 桌面浏览器
- 平板设备
- 手机 H5
- 横屏及竖屏

PC 端采用宽屏沉浸式插画布局。

移动端采用竖屏诗词海报布局，保证日期、诗句、背景画面的完整性。

使用 Tailwind CSS 实现响应式布局，合理使用 clamp、aspect-ratio、Grid 和 Flexbox。

移动端需要考虑安全区域、浏览器地址栏动态高度及 iOS Safari 兼容性。

## 六、交互动效

动画整体要求自然、缓慢、克制，不能影响阅读。

### 6.1 页面初始化

- 背景插画缓慢淡入。
- 日期逐渐显现。
- 诗句按照行或段落依次出现。
- 作者及作品名称最后出现。

### 6.2 日期切换

切换上一天或下一天时：

- 当前诗词缓慢淡出。
- 背景插画交叉渐变切换。
- 日期数字产生轻微翻页效果。
- 新诗句逐渐显现。
- 页面主题色平滑过渡。

### 6.3 季节动态效果

根据季节展示轻量化环境动画：

- 春季：缓慢飘落的花瓣。
- 夏季：萤火虫、轻微水波。
- 秋季：缓慢飘落的枫叶。
- 冬季：轻柔飘落的雪花。

优先使用 CSS Animation 或 Canvas 实现，不引入重量级 3D 渲染库。

动态元素应当与背景插画协调，不能遮挡诗词。

用户可以在设置中关闭动画，同时支持 prefers-reduced-motion。

### 6.4 操作方式

- 点击上一天、下一天切换日期。
- PC 支持键盘左右方向键切换。
- 移动端支持左右滑动切换。
- 点击日期打开日历选择器。
- 点击“今天”快速回到当前日期。
- 支持全屏沉浸模式。
- 全屏 API 不可用时提供隐藏导航的沉浸模式作为替代。

## 七、日历功能

### 7.1 月历视图

提供独立的日历面板，支持查看 2027 年任意月份。

每个日期单元格展示：

- 公历日期
- 农历日期
- 节气
- 传统节日
- 是否为今天
- 是否已收藏
- 是否为当前选中日期

点击任意日期后，关闭日历面板并切换至对应日期的诗词。

### 7.2 年历视图

支持查看 2027 年全年 12 个月的日历。

支持快速跳转至指定月份或节气。

### 7.3 年度进度

展示当前日期在全年中的位置，例如：

- 2027 年第 128 天
- 距离年末还有 237 天
- 年度进度 35.07%

进度计算以当前选中日期为准。

设计为细线进度条或简约数字展示，不要使用复杂仪表盘。

### 7.4 日期范围处理

项目仅包含 2027 年诗词数据。

当真实日期早于 2027 年 1 月 1 日时，默认展示 2027 年 1 月 1 日，并提示距离 2027 年开启还有多少天。

当真实日期晚于 2027 年 12 月 31 日时，默认展示 2027 年 12 月 31 日。

禁止日期导航超出已有数据范围。

## 八、收藏与分享

### 8.1 诗词收藏

支持收藏喜欢的诗词。

使用 localStorage 保存收藏记录，不需要后端服务。

收藏页面支持：

- 查看已收藏诗词。
- 取消收藏。
- 按日期排序。
- 按季节筛选。
- 按作者筛选。
- 点击收藏记录跳转至对应日期。

### 8.2 诗词卡片生成

支持将当前日期、诗词、作者及背景插画生成一张精美的分享海报。

提供以下图片比例：

- 9:16 手机壁纸
- 16:9 PC 壁纸
- 1:1 社交平台分享图
- 3:4 小红书风格分享图

支持导出 PNG 图片。

导出图片时应隐藏页面功能按钮，只保留日期、诗词、作者、背景插画及可选的项目标识。

确保图片来源满足导出使用的授权要求，并处理跨域图片导致 Canvas 无法导出的问题。

### 8.3 分享功能

- 支持复制当前诗句。
- 支持复制完整诗词。
- 支持复制当前日期的分享链接。
- 支持 Web Share API。
- 不支持 Web Share API 时，降级为复制链接。

分享链接示例：

`https://example.com/?date=2027-05-20`

用户打开分享链接后，直接展示对应日期的诗词。

## 九、个性化设置

提供轻量化设置面板：

- 横排诗词 / 竖排诗词
- 开启 / 关闭环境动画
- 开启 / 关闭日期展示
- 开启 / 关闭农历展示
- 开启 / 关闭诗词赏析
- 背景遮罩透明度调整
- 诗词字号调整
- 自动主题 / 浅色主题 / 深色主题
- 简体中文 / 繁体中文

所有设置通过 localStorage 持久化。

## 十二、性能优化

- 保证首屏加载速度。
- 优先加载当天诗词数据及背景图。
- 非核心组件按需加载。
- 日历、收藏、设置、海报生成模块使用合理的懒加载策略。
- 避免不必要的 React 组件重复渲染。
- 日期查询使用 Map 或其他高效索引结构。
- 避免在每次渲染时重新计算全年农历数据。

- 动画优先使用 transform 和 opacity。
- 页面进入后台时暂停非必要动画。

- 支持弱网环境及图片加载失败的降级展示。
- 不允许因第三方图片服务异常导致页面白屏。
- 控制第三方依赖体积。
- 保证移动端滚动及动画流畅。

## 十五、GitHub Actions 自动构建与部署

配置 GitHub Actions。

当代码推送至 main 分支时，自动触发构建流程，并默认部署至 GitHub Pages。

工作流需要包含：

1. Checkout 仓库代码。
2. 安装 Node.js 22 LTS 或其他与依赖兼容的 LTS 版本。
3. 安装 pnpm。
4. 配置 pnpm 依赖缓存。
5. 执行 pnpm install --frozen-lockfile。
6. 执行 ESLint 检查。
7. 执行 Prettier 格式检查。
8. 执行 TypeScript 类型检查。
9. 执行全年诗词数据校验。
10. 执行 pnpm build。
11. 上传 dist 构建产物。
12. 自动部署至 GitHub Pages。

要求：

- 支持 workflow_dispatch 手动触发。
- PR 可以执行代码检查及构建，但不部署。
- 只有 main 分支构建成功后才允许部署。
- 使用 GitHub Pages 官方部署 Actions。
- 正确配置 pages 和 id-token 权限。
- 支持自定义域名。
- 正确处理 Vite base 路径。
- 保证 GitHub Pages 仓库子路径下的静态图片和字体资源正常访问。
- 优先使用 URL Query 参数管理日期，避免静态部署环境下的历史路由刷新 404 问题。
- README 中详细说明 GitHub Pages 的启用和部署流程。
